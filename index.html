01 · Abstract

A model should earn its complexity.

This study investigates whether historical search-performance signals can support content prioritization for potential refresh review. A transparent rule-based baseline was developed first, followed by an audited Decision Tree using historical search and analytics signals. The model was evaluated with grouped validation by client and compared with the baseline on the same held-out groups. The measured results favored the simple baseline: 95.35% accuracy and 94.16% F1 versus 57.62% accuracy and 2.38% F1 for the audited tree. The resulting action queue is therefore framed as directional decision-support for human review, not as evidence that a refresh will cause improved search performance.

02 · Research question

Turn a large content inventory into a review order.

The selected capstone lane is Refresh / Content Opportunity Scoring.

The practical decision is simple: which content items should a reviewer inspect first? The system is intentionally not asked to decide whether a page must be refreshed, rewritten, deleted, or expected to gain traffic.

04 · Methodology

Baseline first. Model second. Audit both.

Proxy target

The Week-5 proxy marks observations where average position is above 20 and clicks are below 5. This is a constructed proxy, not a human-verified “needs refresh” label.

Audited model

A Decision Tree classifier with max_depth=5 uses 12 historical search/analytics features.

Grouped validation

GroupShuffleSplit holds out 20% of client groups. The notebook checks client overlap and uses the same held-out groups for baseline and model comparison.

Leakage control

The two variables that directly construct the proxy target — GSC clicks and average position — are excluded from the audited model.

Why the audit matters: allowing a model to see variables that directly define its target can make performance look stronger than the underlying predictive evidence. The capstone explicitly corrects for that issue.

Where the tree failed

The held-out confusion matrix contains 1,208 false negatives and only 15 true positives. That error pattern is consistent with the measured 1.23% recall and 2.38% F1: the tree missed most proxy-positive cases.

Interpretation: under this grouped validation design, the extra model complexity did not improve the tested proxy task. The transparent baseline remains the stronger measured benchmark.
06 · Limitations

What this study does — and does not — show.

Supported

  • The baseline and tree can be compared on the same grouped test set.
  • The audited tree performed materially below the baseline in this experiment.
  • The queue can be used as directional review prioritization.
  • Leakage risks from target-defining fields were explicitly addressed.

Not supported

  • A claim that refreshing content will cause better rankings.
  • A claim about Google's ranking algorithm.
  • A claim that the queue predicts refresh success.
  • Automatic publishing, rewriting, deletion, or pruning.
Honest framing: words such as observed, measured, directional, associated, and decision-support are preferred throughout this artifact.
07 · Ranked action playbook

Use the queue to focus human attention.

The capstone exports a ranked queue with an opportunity score, action label, and reason code. The top-ranked observations shown in the notebook use REVIEW_REFRESH with the reason code LOW_CLICKS_POOR_POSITION.

Human review checklist

  1. Confirm search demand and data quality.
  2. Check current intent and content fit.
  3. Consider seasonality and recent editorial changes.
  4. Assess business importance.
  5. Only then decide whether a refresh is appropriate.
No-go list: do not automatically publish, rewrite, delete, prune, or claim guaranteed performance improvement from a queue score.
